# Experiments

This directory contains the configurations, launchers, and report builders for
the server experiments. Training, transport, scheduling, and recovery
implementations are shared under `src/sg_exe_trainer/runtime/`.

## Evaluation Map

| Evaluation | Directory | Main question |
| --- | --- | --- |
| E1 | `e1_quality/` | How does stage-local training affect task quality? |
| E2 | `e2_memory/` | How does per-stage GPU memory change with batch geometry? |
| E4 | `e4_throughput/` | How do stage count, scheduling, and link conditions affect throughput? |
| E5 | `e5_recovery/` | What progress and state can be retained across an outage? |

E3 is the physical-phone evaluation and is documented in
`docs/MOBILE_BPFREE_SPLIT_RUNTIME.md`.

Each evaluation directory provides its command line, configuration, expected
inputs, and report builder.

## Running Experiments

Install the repository package and set the source path:

```bash
python -m pip install -e .
export PYTHONPATH=src
```

Models, datasets, and prepared manifests are supplied through each launcher's
arguments. Result roots such as `results/`, `output/`, and `debug_runs/` are
ignored by Git.

The runners record their configuration and command alongside their outputs.
Report builders consume those result directories to generate tables and
figures. The measurement definitions shared by E2, E4, and E5 are documented
in [`MEASUREMENT_RULES.md`](MEASUREMENT_RULES.md).

## Configuration Checks

E1, E2, and E4 launchers accept `--dry-run` to print the commands generated by
a configuration without starting worker processes. This is useful for checking
paths, method selections, and process geometry before a long run.

```bash
python experiments/e1_quality/run_agnews_quality.py \
  --data-root /path/to/artifact-data \
  --dry-run

python experiments/e2_memory/run_gpu_memory.py \
  --data-root /path/to/artifact-data \
  --dry-run

python experiments/e4_throughput/run_e4_1_cpu_transport_scaling.py --dry-run
```
